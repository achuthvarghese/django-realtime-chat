django-realtime-chat · review & proposal

Realtime Chat Rework Plan

Findings from reviewing master (54df6db), a phased plan with one PR per phase, and four UI style directions for the login, signup and chat screens. Nothing has been built yet; this waits for your choices.

Code review findings

SeverityWhereProblem
Criticalrequirements.txtChannels 3.0.5 imports cgi, removed in Python 3.12+. manage.py check fails outright on Python 3.13. Django 4.1 is out of support.
Criticalconsumers.pyNo authentication or membership check. Any visitor, including anonymous ones, can open /chat/<id>, read the live stream and post messages to any room.
Criticalchat.js appendMessageStored XSS: message text and usernames go into innerHTML. get_room_title also wraps user names in mark_safe.
Highchat/migrationsNo migrations committed for Message/Room; the Dockerfile runs makemigrations at build time instead.
Highchat.htmlTwo elements share id="clear-room". The JS binds the first, the mobile back button, so tapping Back clears the history and the trash icon does nothing.
Highchat.jsHard-coded ws:// breaks behind HTTPS. Script crashes when the user has no rooms (search input missing) or opens a room not in their list (activeRoomATag is null).
Highviews.chatLoads any room by id without checking membership, leaking its title and member names.
Highconsumers.receiveMalformed JSON or a missing message key raises and drops the socket; empty messages are saved.
Mediumsettings.pySecret key committed, DEBUG=True, empty ALLOWED_HOSTS, no STATIC_ROOT; debug toolbar always installed.
MediumaccountSignup ignores cleaned_data, username uniqueness is case-sensitive, no auto-login; login authenticates twice; logout works over GET.
MediumProductNo way to start a conversation or create a group from the UI ("Start a new conversation" links to #search). Room search is case-sensitive.
MediumTests / CIZero tests. CI runs only black and isort, on actions/*@v3.

Phased plan

  1. P0

    Foundation and upgrade

    PR 1 · chore/foundation
    • Django 5.2 LTS, Channels 4 + Daphne, Python 3.12; env-based settings (.env.example), debug toolbar dev-only
    • Commit chat migrations; fix Dockerfile and compose
    • pytest + pytest-django + channels test client; CI runs tests and lint
  2. P1

    Security and bug fixes

    PR 2 · fix/security-bugs
    • WebSocket auth and room membership, JSON validation, empty-message guard
    • XSS fixes (textContent, drop mark_safe), wss/ws by protocol, duplicate id, null guards
    • View-level membership check; regression tests for each fix
  3. P2

    Design system and base layout

    PR 3 · feat/design-system
    • Shared base.html, Signal tokens with six palettes × light/dark/system and two densities, focus states
    • Message partials, flash messages, 404/500/403 pages
  4. P3

    Home, login and signup

    PR 4 · feat/auth-screens
    • New public home page; spine-style login and signup with theme pick
    • Inline field errors, show/hide password, password-strength hint, auto-login after signup
    • POST logout, case-insensitive usernames, "next" redirect; form and view tests
  5. P4

    Chat screen rework

    PR 5 · feat/chat-screen
    • Responsive two-pane layout, grouped bubbles, day separators, avatars with initials
    • Reconnecting socket with status indicator, Enter to send, autosize composer, confirm before clearing
    • Drop moment.js for Intl.DateTimeFormat
  6. P5

    New screens

    PR 6 · feat/new-screens
    • Start a direct chat (user search), create a group, presence, typing, unread counts, edit/delete, history pagination
    • Profile and settings: Appearance (palette, mode, density) saved per user
  7. P6

    Documentation

    PR 7 · docs/overhaul
    • README rewrite with screenshots; new docs/: architecture, setup, testing, UI style guide, WebSocket protocol, contributing
    • Each earlier PR also updates the docs it touches

Decisions so far

Base: V1, modern, unlike existing chat apps, combining concept A (transcript, command bar, ⌘K) with B (timeline spine); round 4 picked Signal, with denser threads, more palettes and full responsiveness requested · plain CSS tokens · Phase 5 core features only · phase branches dev-p0… off dev, one PR each to master · login and signup are standalone screens, never shown over the chat.

Suggested new features

Phase 5 · core

  • Start a chat by searching users; create a group and invite members
  • Presence (online dot) and typing indicator
  • Unread counts per room and read state
  • Edit and delete own messages
  • Profile and settings: display name, avatar colour, theme, password change
  • History pagination: load older messages on scroll

Phase 7 · next (deferred)

  • Replies and quotes linked to the original message
  • Reactions with a small fixed set
  • @mentions and browser notifications
  • Slash commands: /clear, /invite, /mute, /me
  • Room switcher on ⌘K and message search
  • Markdown-lite formatting and link previews

Later · platform (deferred)

  • Image and file attachments
  • Password reset by email
  • Mute and archive conversations; pinned messages
  • Rate limiting on the socket; Redis channel layer for production
  • Installable PWA
